- 位置：`app/account/internal/data/data.go` 的 `NewSmsSender`
- 现状：开发者暂时没有阿里云短信的 AccessKey、签名和模板，只实现了把验证码写进日志的 `log` 发送方，生产环境无法发送验证码。
- 处理：配置就绪后实现 `aliyun` 发送方（引入 SDK 前征得同意），并验证发送失败时冷却与计数的回滚。

### TD-26 服务间 gRPC 调用没有认证

- 发现：2026-11-18，重构步骤 2；步骤 3 新增 `SocialInternalService`
- 位置：`api/account/v1/internal.proto`、`api/social/v1/internal.proto`，以及两个服务 `internal/server/server.go` 的 `requiresAuth`
- 现状：内部接口只注册在 gRPC 上、不经过令牌校验，安全性依赖服务网络不对外暴露。服务容器化（步骤 5）后，同一网络中的任意容器都能调用，例如读取任意群的成员列表、探测任意两人是否为好友。
- 处理：步骤 5 起评估 mTLS 或服务令牌。

### TD-25 缓存删除失败时最长有 30 分钟旧数据

- 发现：2026-11-18，重构步骤 2；步骤 3 扩大到 social，优先级由低调为中
- 位置：`app/account/internal/data/user.go`、`app/social/internal/data/group.go` 的 `EvictCache`
- 现状：写操作在数据库提交之后删除缓存，失败只记 WARN，靠 TTL（30 分钟 ±10%）兜底。account 的影响是资料短时间不一致；social 的群成员列表用于发言权限校验，删除失败时被移除或被禁言的成员最多 30 分钟内仍能发言。
- 处理：步骤 4 接入 Outbox 发布器后，改为经事件重试删除。

## 低

### TD-28 布隆过滤器加入失败的重试期间会把新 ID 判为不存在

- 发现：2026-11-19，重构步骤 3
- 位置：`pkg/bloom/bloom.go` 的 `Add`
- 现状：`BF.INSERT` 失败后后台按 1s、2s、4s 重试，重试耗尽才删除就绪标记、触发重建。重试期间过滤器仍是就绪状态且不含新 ID，查询这个新用户或新群会返回“不存在”，并写入 1 分钟的空值缓存。只在 Redis 能读写、但 `BF.INSERT` 单独失败时出现（例如过滤器达到内存上限）。
- 处理：第一次加入失败时立即删除就绪标记（查询改为放行），重试成功后由下一次查询触发重建；或在建群、注册成功后主动删除该 ID 的空值缓存。改动会影响 account 的行为，留到有压测数据后再定。

### TD-29 拉黑与好友申请并发时可能留下一条待处理申请

- 发现：2026-11-19，重构步骤 3
- 位置：`app/social/internal/biz/friend.go` 的 `SendRequest` 与 `Block`
- 现状：两个事务都只读快照、不加锁：A 申请 B 的同时 B 拉黑 A，申请事务看不到拉黑，拉黑事务看不到新申请，结果 B 的收件箱里留下一条来自已拉黑用户的申请。同意它会建立好友关系，但拉黑仍然阻止单聊。
- 处理：收到的申请列表过滤掉已拉黑用户的申请，或在同意时检查拉黑。影响很小，暂不处理。

### TD-27 布隆过滤器的失败分支没有自动化测试

- 发现：2026-11-18，重构步骤 2
- 解决：2026-11-19，重构步骤 3（与步骤 3 一起提交）
- 处理：过滤器抽到 `pkg/bloom`，`test/e2e/bloom_test.go` 连真实 Redis 覆盖重建与查询、加入重试成功、重试耗尽后重建、重建期间变脏再来一轮、始终变脏时保持未就绪、别的实例持锁时跳过、Redis 不可用时放行。
