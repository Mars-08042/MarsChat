# ADR-0003 发送方消息由服务端回显

- 状态：已被 [ADR-0006](0006-message-sync-model.md) 替代（2026-11-18，旧代码已在重构中移除）；原状态为已采纳（追溯记录）
- 日期：2026-11-07 整理

## 背景

用户发出消息后，自己的聊天窗口也要显示这条消息。前端消息列表 `messageList` 中存放的是服务端响应结构（`GetMessageListRespond` 等），而发送时用的是请求结构 `ChatMessageRequest`，两者字段不同（例如响应带 `created_at`，头像路径经过规范化）。

依据：`internal/service/chat/server.go` 文本消息分支中的注释。

## 候选方案

1. 前端发送后直接把消息插入本地列表（注释中称“优化的话前端可以直接回显”）。
2. 服务端落库后，把与接收方相同的响应消息也推送给发送方。

## 决策

采用方案 2。文本和文件消息推送给接收方的同时，也写入发送方连接的 `SendBack` 通道；前端发送后不在本地插入。

例外：音视频通话信令不回显（原因记录在提交 `6624cea` 的 `docs/lessons/av-signaling-no-echo.md`，该文已随旧基线描述删除）。

## 原因

注释原意：前端的 `messageList` 只能存响应结构，不能存请求结构，所以由后端回显、前端不回显。

## 代价与风险

- 发送方要等消息落库并经 WebSocket 往返后才能看到自己的消息，网络或数据库慢时体验明显变差。
- 回显写出成功也会把消息 `status` 改为 1，使该字段不能代表接收方已收到（TD-22）。
- 发送方不在在线表中时，回显代码会对 nil 指针取字段导致崩溃（TD-04）。

## 适用条件

若前端改为本地乐观插入（例如生成临时 ID，收到服务端确认后替换），可以取消回显，届时应新写 ADR 替代本条，并同步调整消息状态的含义。
