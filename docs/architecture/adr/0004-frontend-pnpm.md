# ADR-0004 前端使用 pnpm 管理依赖

- 状态：已采纳（开发者明确要求迁移）
- 日期：2026-11-09

## 背景

前端原使用 Yarn Classic 锁文件；开发者本机已有 pnpm，希望统一依赖管理工具。

## 候选方案

1. 继续通过 Corepack 使用 Yarn 1。
2. 使用本机 pnpm，并从 yarn.lock 导入新锁文件。

## 决策

采用 pnpm 11.22.0，在前端 package.json 中设置 packageManager，使用 pnpm-lock.yaml 作为唯一依赖锁文件；通过 pnpm import 尽量保留原依赖版本。常规安装使用 pnpm install --frozen-lockfile，启动使用 pnpm serve。

导入时临时约束原依赖边及直接依赖版本，完成后移除临时约束元信息并恢复清单的原版本范围，再执行冻结锁文件校验与 peer 检查；最终项目不保留 overrides。16 个直接依赖版本均与原 Yarn 锁文件一致，所有复用包的完整性摘要一致。唯一新增版本是间接依赖 `@achrinza/node-ipc`：9.2.9 → 9.2.10；9.2.9 的 Node 引擎范围只到 22，9.2.10 包含本机 Node 24。除该兼容性解析差异外，未增加或升级其他依赖版本。

## 原因

符合开发者已安装的工具与明确要求，避免维护两套锁文件；不以迁移为由升级业务依赖。

## 代价与风险

pnpm 导入会重新解析依赖图；peer 依赖与目录结构可能和 Yarn 1 不同，安装、lint、编译及页面运行仍需分别验证。本次仅生成和检查锁文件，不安装依赖或运行应用。旧工具链仍报告 ESLint 7 等弃用警告，不在此次迁移中升级。

首次实际安装发现 pnpm 11 会将未审批的依赖脚本作为错误处理。项目通过 `pnpm-workspace.yaml` 的 `allowBuilds` 允许 `vue-demi`、禁用可选的 `core-js` 提示与 `yorkie` hooks 安装；其余依赖保留默认审批要求。安装中止后可重新安装并执行 `pnpm rebuild vue-demi` 补齐兼容入口，不使用全局放开脚本的配置。

## 适用条件（何时需要重新评估）

适用于当前单个 Vue CLI 5 前端项目。升级包管理器或构建工具时，应重新验证锁文件格式与运行兼容性。
